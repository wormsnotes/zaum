# Заумь

Онлайн-газета с главной страницей, новостной лентой по темам и игрой «Змейка». Обычные HTML, CSS и JavaScript: без установки пакетов, сборки и внешних зависимостей.

- Сайт: https://wormsnotes.github.io/zaum/
- Новости: https://wormsnotes.github.io/zaum/news.html
- Публичный репозиторий: https://github.com/wormsnotes/zaum

## Посмотреть на компьютере

Откройте `index.html` в браузере. Интернет для работы сайта не требуется.

## Страницы и материалы

- **Главная** (`index.html`) — ведущий материал, основные новости, ссылки на рубрики и змейка.
- **Новости** (`news.html`) — все материалы с фильтрами «Культура», «Наука». Нажмите на заголовок, чтобы раскрыть статью целиком. Ссылки на рубрики и отдельные статьи можно отправлять другим читателям.

В выпуске оставлен один демонстрационный материал — «У каждой истории теперь есть своя полоса». Рубрика «Наука» пока пуста: при её выборе появляется сообщение об отсутствии материалов.

Сайт использует только четыре базовых цвета: бежевый `#f3f0e7`, чёрный `#272424`, фиолетовый `#7a58bd` и розовый `#f4b0cf`. Прежний зелёный заменён розовым в иллюстрациях, игре и значке вкладки; блок «От редакции» также оформлен на розовом фоне. Все дополнительные текстовые и контурные переменные ссылаются на эти четыре цвета. Прозрачные тени и сетка используют чёрный. Палитра задана в начале `style.css`, игровое поле змейки использует те же переменные.

При публикации ссылки на страницы, стили, скрипты и изображения автоматически получают версию из выбранного коммита и запуска публикации. Вручную менять `?v=...` в HTML больше не нужно: после обновления или отката браузер загрузит нужные файлы.

Чтобы добавить материал, скопируйте блок `<details class="news-article">` в `news.html`. Задайте ему уникальный `id` (например, `new-story`) и тему `data-article-topic`: `culture` или `science`. Замените заголовок, дату, описание и текст. Ссылка на статью будет `news.html#new-story`. Счётчики рубрик пересчитаются автоматически.

Чтобы вынести новость на главную, обновите соответствующий блок в `index.html`: заголовок, краткое описание и ссылки на `news.html#id-статьи`. Добавление новой рубрики потребует также добавить её кнопку в `news.html` и название в объект `titles` файла `site.js`.

Общая шапка и навигация записаны в обеих HTML-страницах: при их изменении обновляйте оба файла. При отключённом JavaScript на новостной странице остаются доступны все статьи, раскрываемые средствами браузера; фильтры появляются при включённом JavaScript.

## Игра

- Нажмите «Играть в змейку» — игра начнётся в отдельном окне.
- Стрелки, WASD (также ЦФЫВ в русской раскладке), свайпы и экранные кнопки управляют змейкой.
- Собирайте фиолетовые яблоки. Каждое яблоко добавляет одно очко и немного ускоряет игру.
- Столкновение со стеной или собственным телом завершает игру.
- Пробел при фокусе на поле или кнопка «Пауза» останавливают игру.
- «Заново» начинает новую попытку, Esc или крестик закрывают окно.
- При смене вкладки или потере фокуса окна игра автоматически ставится на паузу.
- Личный рекорд сохраняется в браузере, если браузер разрешает локальное хранилище. Это не общий рейтинг посетителей.

## Публикация и обновления

GitHub Pages публикует сайт через workflow **Publish website**. Настройки находятся в репозитории: **Settings → Pages → Source → GitHub Actions**. Собственный домен и платный хостинг не нужны.

После изменения файлов выполните в терминале PowerShell:

```powershell
cd 'C:\Work folder\zaum'
git add .
git commit -m "Update website"
git push
```

После `git push` workflow проверяет инструменты версионирования, публикует сайт и сохраняет метку `site-N` — например, `site-1`, `site-2`. Метка создаётся после успешной публикации и указывает на точный исходный коммит. Состояние видно во вкладке **Actions**; обновление может занимать несколько минут.

## Версии и быстрый откат

Текущее принятое оформление сохранено как **`v1.0.0`** (коммит `ea9a2e0`). Метка **`site-0`** обозначает эту же исходную опубликованную версию. Все следующие успешные публикации получают свои неизменяемые метки `site-N`.

- [Список сохранённых версий](https://github.com/wormsnotes/zaum/tags).
- [Публикация и откат](https://github.com/wormsnotes/zaum/actions/workflows/publish.yml).
- [Версия, которая сейчас открывается посетителям](https://wormsnotes.github.io/zaum/version.json).

Чтобы быстро вернуться к предыдущей публикации:

1. Откройте **Actions → Publish website → Run workflow**.
2. Оставьте ветку **main**.
3. В поле **version** оставьте `previous` и нажмите **Run workflow**.
4. Дождитесь зелёной отметки успешного выполнения. Адрес сайта останется прежним.

Можно также ввести конкретную метку (`v1.0.0`, `site-0`, `site-2`) или SHA любого коммита из истории репозитория. Для возврата к последнему коду введите **`main`**.

`previous` выбирает предыдущий отличающийся исходный коммит среди записанных публикаций. Повторная публикация одного и того же коммита не становится отдельной целью отката. После отката его результат также получает метку `site-N`, поэтому можно вернуться и к состоянию до отката. Повторный запуск уже успешного задания публикует тот же исходный коммит, что и первый запуск.

**Быстрый откат меняет опубликованный сайт, сохраняя историю и код ветки `main`.** Следующий `git push` снова публикует актуальную ветку. Если хотите продолжать разработку именно от сохранённого оформления, восстановите его файлы отдельным коммитом; например, для принятой версии:

```powershell
git fetch origin --tags
git restore --source v1.0.0 -- index.html news.html style.css site.js script.js favicon.svg
git add index.html news.html style.css site.js script.js favicon.svg
git commit -m "Restore website version v1.0.0"
git push
```

Метки версий не перезаписывайте и не удаляйте. Файл `version.json` создаётся при публикации: он содержит метку, полный SHA исходного коммита и время подготовки. Служебные скрипты, тесты, README и файлы Git в опубликованный сайт не попадают.

Локальная проверка механизма версий:

```powershell
python -m unittest discover -s tests -v
```

На этом компьютере Git в этой папке использует существующую авторизацию GitHub CLI из Ubuntu в WSL (пользователь `natasha`, аккаунт GitHub `wormsnotes`). Настройка помощника авторизации хранится только в локальном `.git/config`; паролей и токенов в файлах сайта нет. Для `git push` Ubuntu в WSL должна быть доступна. На другом компьютере нужно отдельно авторизовать GitHub.

Обновления можно также загружать через **Add file → Upload files** на GitHub, подтверждая **Commit changes**. `index.html` и остальные файлы сайта должны оставаться в корне репозитория.

## Файлы

- `index.html` — главная страница и окно игры.
- `news.html` — новостная страница с полными текстами.
- `site.js` — фильтрация рубрик, открытие статьи по ссылке и год в подвале.
- `style.css` — оформление и адаптация для телефона.
- `script.js` — логика змейки, управление и рекорд.
- `favicon.svg` — значок вкладки браузера.
- `.nojekyll` — отключает ненужную для этого сайта обработку Jekyll.
- `.github/workflows/publish.yml` — публикация, ручной откат и сохранение метки версии.
- `scripts/prepare_site.py` — выбор версии, экспорт файлов и обновление ссылок для браузерного кэша.
- `tests/test_versioning.py` — проверки отката, сохранности ветки и файлов выбранного коммита.

Все пути к ресурсам относительные: сайт работает и на GitHub Pages в подпапке `/zaum/`, и при открытии с компьютера.
